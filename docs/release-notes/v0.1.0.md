First public pre-release of **qget**: fast, verified, resumable downloads, with archives extracted while they download. Linux only (x86_64 and aarch64).

> **Pre-release.** Command-line flags and the library API may change before 1.0. Please report problems in Issues.

## Highlights

- **Stream-extract** (`qget -x DIR URL`): downloads a `.tar.lz4`, `.tar.zst`, `.tar.gz` or `.tar.xz` over parallel connections and extracts it as it arrives. The archive is never stored, so no second copy is needed on disk. LZ4 blocks and zstd frames decode in parallel when the archive allows it. The extracted tree only appears in `DIR` after the download is verified.
- **Crash-safe resume**: data is fsynced before it is recorded in an append-only, checksummed journal. Kill qget at any point (including `kill -9`) and re-run the same command to resume with byte-exact results; the test suite does this dozens of times per run.
- **Integrity checking while downloading**: `--checksum sha256:… | sha512:… | blake3:…`, `--checksum-url` (sha256sum files), `Repr-Digest` headers, and `<url>.sha256` auto-discovery when extracting. On a mismatch qget exits 5 and never finalises the output.
- **Correct range handling**: every request carries `If-Range`. `Content-Range` and byte counts are checked exactly, a server that ignores `Range` is never stitched in, and a file that changes mid-download is detected (exit 6).
- **Adaptive parallel HTTP**: a connection controller, work stealing, straggler hedging and end-game duplication. Also mirrors (`--mirror`), `429`/`503` handling with `Retry-After`, `--refresh-cmd` for expired signed URLs, `--limit-rate` and `--polite`.
- **Reproducible scheduling**: `--seed`, `--trace FILE`, and `qget replay FILE` reproduces every decision exactly.
- **wget-style CLI**: `-O`, `-P`, `-c`, `-q`, `-i`, `--header`, `-U`, `-t`, `-T`, plus `--explain` (bottleneck report), JSON progress, documented exit codes, a config file, a man page and shell completions.
- **Peer-to-peer** (the `-p2p` binary): `qget yeet FILE|DIR` / `qget yoink CODE|TICKET` over iroh QUIC with hole punching and relay fallback. Every 1 MiB is verified against the file's BLAKE3 root before it is written. Also supports short codes via a self-hosted `qget mailbox` (SPAKE2), multi-peer swarms, hybrid peer and HTTP mirror downloads, and `--seed`.

## Performance: honest status

Measured on loopback with emulated server limits (`bench/results/2026-11-04-1024m.md`), plus one real Cloudflare R2 test:

| Scenario | qget | aria2c `-x16 -s16` | curl / wget |
|---|---|---|---|
| Download **and extract** 387 MiB `.tar.lz4`, 25 MB/s per connection | **4.8 s** | 7.9 s (download, then `tar`) | 16.4 s (`curl \| lz4 \| tar`) |
| 1 GiB, 25 MB/s per connection | 4.1 s | **2.7 s** | 43 s |
| 29 GiB from Cloudflare R2 (real network) | 584 MiB/s | **878 MiB/s** | — |

**Stream-extract is the clear win.** For plain downloads aria2c is currently faster. The likely causes are a slow connection ramp-up, `fdatasync` stalls in the write path, and request gaps between blocks. These are the focus of the next release.

Each archive contains the binary, a man page and bash/zsh/fish completions. Verify downloads with the matching `.sha256` file, or with GitHub's build provenance:

```sh
sha256sum -c qget-v0.1.0-linux-x86_64.tar.gz.sha256
gh attestation verify qget-v0.1.0-linux-x86_64.tar.gz -R dharrsan-hq/qget
```

## Known limitations

- Linux only. HTTP/3 is an experimental build-time feature and is not included in these binaries.
- Resuming an extraction requires `--keep-archive`; without it, an interrupted extraction restarts.
- gzip and xz archives decode on a single thread.
- There is no public short-code mailbox. Use tickets, or run `qget mailbox` yourself.
- P2P has been tested on loopback and LAN, not yet across NAT types.
- Fuzz targets exist but have not yet had a long fuzzing run.
